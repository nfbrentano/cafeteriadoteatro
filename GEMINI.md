# Regras de Fluxo de Trabalho (Workflow Rules)

- **Gestão de Tarefas (SDD):** Sempre que finalizar a implementação de uma funcionalidade ou atividade descrita em um arquivo Markdown dentro da pasta `SDD/`, você DEVE mover este arquivo concluído para a pasta `SDD/CONCLUIDAS/` como última etapa do processo. Para uma SDD ser movida para `SDD/CONCLUIDAS/`, é obrigatório que ela tenha todos os CAs marcados com `[x]` (ou status "Concluída com ressalvas" apontando a SDD de correção para cada ressalva) e o cabeçalho padronizado.
- **Criação de Novas Features:** Sempre que for solicitada a criação de uma nova feature ou funcionalidade, você DEVE obrigatoriamente iniciar o processo criando um arquivo `.md` na pasta `SDD/`. Utilize como base estrutural o template disponível em `SDD/MODELO_ATIVIDADE.md`. Este arquivo servirá como especificação inicial e deverá ser apresentado para minha revisão. Somente após a aprovação deste documento é que o plano de implementação e a codificação devem ser iniciados.
- **Testes Funcionais Automatizados Obrigatórios:** Toda implementação de nova funcionalidade ou tarefa descrita em SDD DEVE obrigatoriamente incluir uma suíte de testes funcionais automatizados (em `tests/caf-XXXXXX-*.test.js` ou equivalente) cobrindo todos os cenários possíveis (caminho feliz, limites/borda, tratamento de erros e casos negativos de cada Critério de Aceitação) e que importe código real da aplicação. A tarefa só pode ser considerada finalizada e movida para `SDD/CONCLUIDAS/` após `npm test` e `npm run build` passarem com 100% de sucesso.
- **Validade e Integridade dos Testes Funcionais:** Um Critério de Aceitação funcional só pode ser considerado atendido por testes que executem o código real da aplicação (via harness/import/DOM com mocks de borda). Testes que apenas leiam o texto de arquivos por regex, ou que reimplementem a lógica de negócio dentro do próprio arquivo de teste sem chamar a aplicação, são estritamente proibidos e não contam como cobertura funcional. Arquivos de catálogo (`supabase/snapshots/` e `tests/fixtures/schema-snapshot.json`) devem ser gerados a partir do banco/diagnóstico real e nunca criados ou editados manualmente.
